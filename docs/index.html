The problem

Similarity search only reaches half the memory

Long-term memory lets a conversational agent stay coherent across sessions, follow through on commitments made weeks earlier, and adapt to each user. But today's LLM-backed memory is reachability-bounded by query–content similarity, lexical or dense. That works when a query and a memory share surface features such as wording or named entities — the descriptive regime. It misses an equally common regime where query and memory share no surface form and are tied only by a latent semantic arc — the associative regime. Prevailing memory systems collectively fail on this second half.

T-Mem covers both. At each of two evidence granularities — single facts (items) and full exchanges (scenes) — it instantiates one descriptive and one associative trigger family, so every memory stays reachable from surface-similar and relevance-bound queries. These write-time rehearsals — the engineering counterpart of episodic future thinking — are what we call triggers.

Descriptive recall — solved

Query restates the memory

The query reuses the same wording, names the same entities, or anchors the same time and place. Nearest-neighbour search over BM25 or dense vectors finds it. Every prior memory system — flat RAG, graph memory, agentic and OS-style kernels — lives here.

“When did Caroline join the support group?” → the fact that mentions the support group.
Associative recall — the blind spot

Query and memory share no surface

What binds them is a latent arc — a causal link, or the continuation of a shared situation. The target lies far beyond any realistic top-K under similarity retrieval, so prior systems miss it. This is the half T-Mem is built to cover.

“What venue suits the team dinner?” → a fact recorded months earlier about a colleague’s allergy.
Contributions

What's new

01 · framing

A 2×2 recall space

Granularity (item / scene) × orientation (descriptive / associative). Prior memory systems occupy only the descriptive half.

02 · method

One trigger per quadrant

Entity & Scene cover the descriptive half; Bridge & Horizon cover the associative half that similarity search cannot reach.

03 · architecture

Triggers off the evidence path

How a memory is reached is decoupled from what is reached. Triggers guide retrieval only; scenes and items remain the evidence.

04 · results

State of the art, both benchmarks

80.26% on LoCoMo (+3.25 pp) and 74.81% on LoCoMo-Plus, collapsing the cross-benchmark gap to a single-digit margin.

Approach

Construct, then retrieve top-down

A four-stage write pipeline builds a typed memory graph over scenes, items, and topic labels. At read time, a top-down topic → scene → item cascade fuses lexical and dense rankings with RRF, and the associative triggers bypass the topic prefilter — so relevance-bound cues aren't gated by the very similarity test they're designed to escape.

The write pipeline, stage by stage

Stage 1 · segmentation

Scenes & topics

A boundary-detector LLM segments the dialogue by event closure, not by session — one event can span sessions, one session can mix events. A topic module then tags each scene with growing, multi-label topics.

Stage 2 · extraction

Atomic & connected items

Per topic, the extractor distils two item types in one call: atomic facts anchored to a single scene, and connected facts that preserve a cross-scene link before retrieval ever sees it.

Stage 3 · item triggers

Entity + Bridge

Each item gets an Entity trigger (a superordinate concept, for surface-similar queries) and a Bridge trigger (a future situation where the fact would matter, with a one-clause rationale).

Stage 4 · scene triggers

Scene + Horizon

Each scene gets a Scene trigger (situation, object, event, emotion) and a Horizon trigger that projects it onto forward-looking channels, reachable from a related-but-different future query.

Evaluation

Benchmarks & baselines

Two long-term-memory benchmarks of multi-session dialogue spanning weeks to months. LoCoMo-Plus adds a Cognitive subset that probes exactly the associative axis — its cue and answer are bound by narrative or causal links, placing the target far beyond any realistic top-K under similarity retrieval.

LoCoMo
10 conversations

Single-hop, Multi-hop, Temporal, and Open-domain questions over long multi-session chats.

LoCoMo-Plus
Cognitive subset

Injects associative probes whose cue and answer share no surface form — the direct test of the blind spot.

Compared against  Mem0 · Zep · Memobase · MemU · Supermemory · MIRIX · MemOS · HyperMem on LoCoMo, and Mem0 · SeCom · A-Mem · MemOS · HyperMem plus closed-source LLM references (GPT-4o, Gemini-2.5-Pro) on LoCoMo-Plus. Reading the columns

Each question type lines up with a design point

Single-hop and Temporal map to the scene–item evidence layer, the Entity route, and the Scene trigger. Multi-hop maps to the Bridge route and the topic pre-filter, which together feed cross-scene evidence beyond a single similarity hit. Open-domain maps to persona traits, where T-Mem's Persona channel complements the evidence. The gains are where the design predicts them.

Closing the associative gap

The scene triggers carry LoCoMo-Plus

On the associative benchmark, removing the scene-level Horizon trigger costs up to 12.5 pp, and removing both scene triggers costs 22.2 pp — while the same ablations barely move LoCoMo. This is direct evidence that the associative half is what collapses the cross-benchmark gap to 5.45 pp, roughly five times tighter than the strongest prior system.
